## Phase D — Full monolith decomposition (after Phases 1–2; owner chose full decomposition)

**Global method: mixin extraction, not state refactor.** `BotEngine`/`OrderManager` are God-classes whose methods close over shared mutable `self` state and locks. The only behavior-preserving mechanical move is cut/paste of method blocks into mixin classes in new modules, recomposed via `class OrderManager(_StateMixin, _ExecutionMixin, …)` — `self` semantics, lock identity, and `monkeypatch.setattr` MRO resolution stay identical. No state-ownership or signature changes ("clean up while moving" is forbidden).

**Shim policy:** every old import path becomes a permanent facade re-exporting the full public surface (`core/bot_engine.py`, `core/order_manager.py`, `core/mcp_brain.py`, `dashboard.py`, `config/__init__.py`). Facades are never deleted — mass-rewriting importers across ~2,002 tests/scripts/skills is pure risk for zero behavior benefit.

**#1 hazard: monkeypatch targets on module globals.** Tests patch names like `core.mcp_brain.ENTRY_COOLDOWN` (also imported by `mcp_strategy_scorer.py:24`), `core.order_manager.<helper>`, `config.<CONST>`. Rule: D0 builds a checked-in grep inventory of every patch target on the five monoliths; each symbol either stays physically in the facade (internal call sites reference the facade) or its tests are updated in the same commit as its move.
